Milestone editor redesign, with live visual preview

Prototype for wayframe#102 (ticket t34). #92/t19 already locked the property set this editor needs to expose — markerShape, markerScale, fontScale, titleLabelPosition, dateLabelPosition, hidden, color, phaseShape, phaseSize — and named this ticket the owner of "turning this property set into an actual editor UI without it becoming an unusable wall of controls." Two real layouts below, sharing the same field set and live state — toggle between them.
Verdict Variant 1 (sticky preview rail + collapsible sections) — the preview needs equal room in all four directions to show titleLabelPosition/dateLabelPosition meaningfully; a slim top strip can't. Collapsible sections also let Content and Appearance stay visible together when a user wants to cross-check, where tabs force a choice.

Rejected alternatives

  • Variant 2 (top preview strip + tabs), built above for comparison — the strip is tall enough for the marker itself but not for a label pushed to top or bottom, which is exactly the property this preview most needs to demonstrate. Tabs also hide Content while editing Appearance, adding a click most users won't need — a collapsed section stays inline and multiple sections can be open at once.
  • Distributed inline mini-previews (a tiny swatch icon printed next to each control instead of one consolidated canvas) — not built, rejected on inspection: it can show "what does a star look like" but not "what does a scaled star with a category color and a top-attached title look like together," which is the actual point of a live preview once more than one Appearance property is in play at once.
  • A dedicated wizard/stepper (Content → Appearance → Relationships as forced sequential steps) — rejected without building: nearly every edit here is a single-field tweak to an existing item, not a first-time creation flow: forcing a multi-step sequence to change one marker shape is strictly worse than either variant above.
