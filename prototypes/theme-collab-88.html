Theme document model & collaborative edits — wayframe#88

Question this demo answers: once Theme is Portfolio document content (#76/#82), how does storing it as one field-level model (a base preset id plus a sparse override map, resolved live — same idiom #87 settled for Scenarios) compare against the naive alternative of storing the whole resolved Theme as one JSON blob field, when two collaborators edit the shared Theme at the same time? And does the OKLCH laneRamp generator (3 numbers: lightness, chroma, start hue — not per-lane hex values) survive becoming a hand-editable field under either model?

Two peers below each hold their own local view of the Portfolio's Theme and fire edits independently. Watch the two converged results diverge — that divergence is the answer to "who wins."

Peer A's editor

Edits apply immediately to the field-level model. Under the blob model, each edit is written on top of whatever Peer A last saw — pulls the latest blob first.

Peer B's editor

Same mechanism, independent peer. Neither peer sees the other's edit until they explicitly refresh (blob model) — the field-level model needs no refresh at all.

Converged — field-level model (proposed)

{ baseId, overrides: {field → value} }, each key merged independently by whichever edit has the latest logical clock — exactly the base+override idiom #87 used for Scenario deltas.

Converged — whole-blob model (rejected)

One field holds the entire resolved Theme as a single JSON value. Merged by last-write-wins on that whole value — whoever's write lands last overwrites the entire object, not just what they touched.

Peer snapshots (blob model only — this is why it loses edits)

Each peer's write under the blob model is built from their own last-seen snapshot, not the live server state. A stale snapshot at write time is what causes a silent overwrite.

Where the two models disagree

Any row highlighted above is a field the field-level model preserved and the blob model silently lost (or vice-versa isn't possible — the blob model never has data the field model lacks).
