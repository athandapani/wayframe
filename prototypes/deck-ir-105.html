Deck IR — one shared shape model, two renderers

Question this settles (wayframe#105): a Deck should describe a slide as real, editable shapes and text — not a screenshot, which is all today's export does — and that same description has to drive both a PowerPoint file (via pptxgenjs) and a Google Slides deck. Those two renderers don't support the same things (#t6/#t7's capability probes), so this prototype pins down: what the shared model stores, and how each renderer decides what it can and can't honor.
